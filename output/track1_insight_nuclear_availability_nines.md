# Track1 洞察：核电高可靠要求多少个9？

> 分析日期：2026/06/09
> 基于：track1_nuclear_safety_IC_reliability_quantitative_requirements.md、track1_analysis_software_reliability_and_hw_sw_coordination.md

---

## 核电可用度"几个9"——关键数字

| 指标 | 量化值 | 等效"9"的数量 | 标准出处 |
|------|--------|-------------|---------|
| **RPS(反应堆保护系统)可用性** | ≥ 99.99% | **4个9** | IEEE 603 + IEEE 7-4.3.2 |
| **A类系统 PFD(每需求危险失效率)** | ≤ 10⁻⁵ /需求 | **5个9**(每次保护动作) | IEC 61513 / IEEE 603 §5.15 |
| **SIL 4 PFH(连续模式)** | ≤ 10⁻⁹ /h | 等效年可用度 ~**5个9** | IEC 61508 Table 3 |
| **堆芯损坏频率 CDF** | ≤ 10⁻⁵ /堆年 | **5个9**(每年) | IAEA INSAG-12 / SSR-2/1 |
| **大量早期释放频率 LERF** | ≤ 10⁻⁶ /堆年 | **6个9**(每年) | IAEA INSAG-12 |

---

## 核心洞察

### 1. 不是简单的"某个固定9"——是分层分级体系

核电不追求一个笼统的"几个9"，而是按**安全分级(A/B/C)** 设定不同等级：

- **A类（最关键，防堆芯损坏）**：PFD ≤ 10⁻⁵ = **5个9/每次需求**，SIL 3~4，4重冗余(2oo4表决)
- **B类（防大量放射性释放）**：PFD ≤ 10⁻⁴ = **4个9/每次需求**，SIL 2~3，2oo3冗余
- **C类（其他安全相关）**：PFD ≤ 10⁻³ = **3个9/每次需求**，SIL 1~2，1oo2冗余

越关键的功能，要求的9越多。**A类系统是核心——5个9起步**。

### 2. 可用度 ≠ 安全度——核电度量的本质差异

| 度量维度 | 含义 | 核电要求 |
|---------|------|---------|
| **可用度(Availability)** | 系统随时可执行功能的时间比例 | RPS ≥ 99.99% (4个9) |
| **安全完整性(PFD/PFH)** | 需要动作时**成功执行**的概率 | ≤ 10⁻⁵/需求 (5个9) |
| **安全目标(CDF)** | 整个反应堆不发生堆芯损坏的年度概率 | ≤ 10⁻⁵/堆年 (5个9) |

关键洞察：**核电最核心关注的不是"系统一直在线"（4个9），而是"需要动作时绝对不能失败"（5个9）**。这与云服务的"可用度"思维根本不同。

### 3. 为什么不是更多9？——纵深防御哲学

单独一个系统做到5个9已经极难，核电的策略不是**单系统极限堆9**，而是：

**多层独立防线组合效果**：
```
第1层：预防偏差（高质量设计）
第2层：检测和控制异常
第3层：设计基准事故自动响应（A类系统 5个9）
第4层：严重事故缓解（多样化后备 DAS）
第5层：场外应急
```

**任何单层4~5个9，多层叠加后整体CDF达到10⁻⁵/堆年（5个9），LERF达到10⁻⁶/堆年（6个9）**。不是靠某一层堆到7~8个9，而是靠**多层独立防线乘积效应**。

### 4. SIL 4的理论极限——如果单系统极致

如果单系统达到 SIL 4 连续模式最高要求 PFH = 10⁻⁹/h：

```
年度危险失效概率 = 10⁻⁹ × 8760 h ≈ 8.76×10⁻⁶
等效可用度 ≈ 99.9991% → 约 5个9
等效 MTBF_dangerous ≈ 10⁸ h ≈ 11,400年
```

但实际工程中**没有单系统敢声称达到这个水平**——SIL 4 的达成依赖冗余架构 + 多样性防御，而非单设备可靠性。

### 5. 对5GC/云核心网的映射

| 核电 | 等效"9" | 5GC映射 |
|------|--------|---------|
| A类 PFD ≤ 10⁻⁵ (5个9/需求) | 每次切换/迁移不丢会话 | AMF/SMF 会话切换成功率 ≥ 99.999% |
| RPS可用性 ≥ 99.99% (4个9) | 网元在线时间 | 核心网元可用性 ≥ 99.999% (5个9) |
| CDF ≤ 10⁻⁵/堆年 (5个9/年) | 年度全局故障 | Region级年度全损概率 ≤ 10⁻⁵ |
| 纵深防御5层叠加 | 多层乘积 | 预防→检测→AZ内恢复→跨AZ→全局调度 |

**云核心网目标比核电仪控可用度还高1个9（5个9 vs 4个9）**，这是因为云服务度量的是"时间比例"，而核电度量的是"关键时刻不能失败"——后者容忍更多的在线率损失（可以停堆检修），但对"需要动作时必须成功"的要求极严。

---

## 总结

核电高可靠不是追求某个单一的"几个9"，而是**A类系统5个9/每次需求 + 纵深防御5层叠加 → 整体安全目标达5~6个9/年**。核心智慧在于——不信任单层防线，用多层独立4~5个9的乘积效应实现系统级6个9。

这一思路对云核心网的启示是：不要试图让单个网元堆到6~7个9，而是构建多层独立防线（预防→AZ内→跨AZ→跨Region→全局应急），每层4~5个9，通过乘积效应实现系统级更高可靠性。
