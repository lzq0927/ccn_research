# 根技术 3：时间因果约束（Temporal Causality Constraint）

> **一句话本质**：原因必须先于结果。时间线是分布式系统里**唯一的全局时钟**，而时间戳是机器生成的——LLM 唯一伪造不了的证据。这是最廉价也最严格的因果检验。

如果说 [02 拓扑先验](02_结构因果先验_Topology-Graph.md) 给的是**空间约束**，本根技术给的是**时间约束**。两者正交，合在一起把假设空间夹到一个很小的角落。checkout 案例里 H2（支付网关慢）正是死在本根技术手上。

---

## 1. 理论谱系：从 Hume 到 Granger

### 1.1 Hume 的因果恒常连结

David Hume（1739）把因果归结为三种要素的恒常连结：**时间上的先后（priority）、空间上的邻近（contiguity）、恒常伴随（constant conjunction）**。其中"原因必须先于结果"是最少争议的一条——它几乎是因果概念的定义性成分。

> **必要非充分**：A 早于 B 是 A 导致 B 的**必要条件**，远非充分条件。但正因为是必要条件，它作为**反证**极其好用：观察到 B 早于 A，就能**一票否决"A 导致 B"**。这是 modus tollens 在时间维度的直接应用（与 [01](01_反证优先_Falsification-First.md) 同构）。

### 1.2 Granger 因果（时序因果的工程化）

Clive Granger（1969）给"时间因果"一个可操作的定义：

> 若用 X 的过去值预测 Y 的未来，比仅用 Y 的过去值预测**显著更好**，则称 X "Granger-causes" Y。

形式化：比较两个回归的残差方差

```
受限模型：  Y_t = f(Y 的历史)              → 残差方差 σ²_restricted
完整模型：  Y_t = f(Y 的历史, X 的历史)    → 残差方差 σ²_full
若 σ²_full < σ²_restricted（统计显著）→ X Granger-causes Y
```

AWS 的工程实现是 Granger 因果的**简化、离散、事件化版本**：

- 不做回归，只比对**时间戳**：候选原因的 onset 必须 ≤ 故障的 onset。
- 把"显著更好"换成"时间反向 → 直接淘汰"。

这是用最便宜的方式拿到 Granger 因果的核心收益——**因果方向的判定**。

### 1.3 为什么时间维度对 LLM 特别"硬"

| 维度 | LLM 能否伪造 | 作为反证的硬度 |
|---|---|---|
| 文本描述（"日志里有 error"） | ✅ 能幻觉 | 弱（需交叉验证） |
| 指标数值（"CPU 90%"） | ✅ 能编 | 中（需查原始源） |
| 因果叙述（"因为 A 所以 B"） | ✅ 能合理化 | 弱 |
| **时间戳**（"onset = 14:03:17"） | ❌ 伪造不了 | **硬**（来自机器时钟/日志） |

时间戳来自系统时钟、日志行、事件流——这些是机器生成的客观记录。LLM 可以**误读**时间戳（解读错），但**不能无中生有**一个真事件的时间戳，因为反证检验时会去原始源核对。**这是为什么时间因果是 7 项里"最廉价也最严格"的反证来源。**

## 2. 它要解决的根本问题：因果方向判定的对称性破缺

### 2.1 相关是对称的，因果是有向的

统计相关是对称的：`corr(A,B) = corr(B,A)`。但因果有向：A→B ≠ B→A。**纯数据无法区分** A→B 和 B→A（这与 [02](02_结构因果先验_Topology-Graph.md) 提到的马尔可夫等价类是同一困难）。

要破这个对称，必须引入方向性信息。两个来源：

- **结构方向**（A 架构上调用 B）→ [02 拓扑](02_结构因果先验_Topology-Graph.md)。
- **时间方向**（A 的 onset 早于 B）→ **本根技术**。

### 2.2 checkout 案例的 H2：时间反证的教科书例子

> 假设 H2："支付网关响应慢导致 checkout 延迟。"
> 反证探针："支付网关什么时候开始慢？"
> 反证内容："支付网关变慢的 onset **晚于** checkout 延迟的 onset。"
> 判决：❌ eliminated——它是 checkout 延迟的**症状**，不是原因。

这里发生的事情，本质是 Granger 因果的反向应用：不是去证明"网关 Granger-causes checkout"，而是发现**"checkout Granger-causes 网关"在时间上更成立**（checkout 先变，网关后变）。于是 H2 的因果方向被证伪，整个假设被淘汰——尽管它有大量"支持证据"（网关确实慢了、确实相关、确实在调用链上）。

> **这就是反证优先（[01](01_反证优先_Falsification-First.md)）在时间维度的胜利**：一条时间反证，推翻了一堆支持证据。逻辑闭合胜过归纳堆叠。

### 2.3 反模式：忽略时序的"同时异常"陷阱

一个常见的失败模式：发现 DB CPU 高、延迟高、错误率高**同时**出现，于是声称"DB CPU 高是根因"。问题：三者同时出现只说明**相关**，不说明因果。真实根因可能是更早的一个事件（一次部署、一次配置变更、一次流量突增），DB CPU 高只是级联症状。

AWS 的应对：把**事件时间线**作为第一类证据（母文档第二节的数据源表），强制要求每个假设的 onset 与故障 onset 对齐或更早。"同时"不够——必须是"之前"。

## 3. 机制内核：事件时间线作为全局时钟

### 3.1 为什么需要"全局时钟"

分布式系统的时钟是**不可靠的**：时钟漂移、NTP 校正跳变、跨 AZ 的时钟差、闰秒。如果直接用原始时间戳做因果判断，会被时钟噪声污染。

AWS 的工程选择：**事件时间线**不依赖绝对时钟，而依赖**因果排序（happens-before）**。

- 用 Lamport 式的逻辑时间（事件之间的偏序）作为主轴。
- 绝对时间戳只作为辅助（当需要跨系统对齐时）。
- 关键判定不是"A 的时刻 < B 的时刻"，而是**"A 在因果上先于 B"**——这对时钟噪声鲁棒。

> 母文档交叉验证矩阵第 2、3 条："时间线是唯一的全局对齐基准""因果方向由时间戳判定（Granger 因果的工程实现）"。注意它说的是"时间线"作为基准，不是"裸时间戳"——这是为了规避时钟不可靠。

### 3.2 onset 对齐规则（判决层）

```
对每个假设 H（候选原因 C，候选故障 F）：

  t_C = C 的 onset（如部署时刻、配置变更时刻、资源耗尽时刻）
  t_F = F 的 onset（告警首次触发时刻，或指标首次越界时刻）

  if t_C is unknown or t_F is unknown:
      H.verdict = "hypothesis"          # 时间证据缺失，不能下根因判决
  elif t_C > t_F:                        # 原因晚于结果 → 时间反证
      H.verdict = "eliminated"
      H.eliminated_by = "temporal: cause-onset after effect-onset"
  elif t_C <= t_F + Δ(tolerance):        # 对齐（含容差，吸收时钟漂移/检测延迟）
      # 时间维度通过，交给其它维度（拓扑、多模态）继续检验
      pass
```

`Δ(tolerance)` 是关键工程参数：太小会被时钟噪声误杀，太大会放过真症状。它应该与系统的**检测延迟**（从故障发生到被指标捕获的滞后）+ **时钟漂移上界**匹配。

### 3.3 时间线作为"第一类证据"

母文档第二节的数据源表里，事件流（部署/配置/扩缩容/告警）被赋予特殊地位——**严格时间排序**。这不是普通的证据模态，而是**所有其它模态必须能映射到的基准轴**：

```
                    Metrics    Logs    Traces    Config    Events(时间线)
                    ───────    ────    ──────    ──────    ─────────────
假设 H              ✓          ✓       ✓         ✓         ✓
                                                    ↑
                                       其它模态的每个点都要能落到 Events 轴上
```

指标、日志、trace 里的每条证据，都要能回答"这件事发生在时间线的哪个位置"。**不能映射到时间线的证据是无效证据**——因为它无法参与因果方向判定。

## 4. 在 AWS DevOps Agent 中的具体落地

| 环节 | 时间因果的体现 |
|---|---|
| **Context Acquisition** | 解析影响范围 + **时间窗**；检查"最近部署活动"（候选原因的时间锚）。 |
| **Data Collection** | 事件流严格时间排序；所有模态对齐到事件时间线。 |
| **Investigation** | 每个假设做 onset 对齐检验；时间反向 → 淘汰（案例 H2）。 |
| **Mitigation** | （间接）blast radius 评估考虑"变更时间窗内受影响的服务"。 |

母文档交叉验证矩阵的核心规则里，时间相关的有两条（第 2、3 条），是矩阵的"骨架"——没有时间轴，整个交叉验证无从对齐。

## 5. 工程实现清单

- [ ] **统一事件时间线**：把部署、配置、扩缩容、告警、指标越界都归一化成带 onset 的事件，统一排序。
- [ ] **因果时间优先于绝对时间**：能用 happens-before 就不用墙钟；绝对时间只做跨系统辅助对齐。
- [ ] **onset 检测器**：为每个模态建一个"首次越界时刻"检测器（CUSUM/变点检测），给假设提供 t_C、t_F。
- [ ] **容差 Δ 的标定**：基于检测延迟 + 时钟漂移上界标定，不同模态不同 Δ。
- [ ] **时间反向 = 硬规则**：决策层用代码实现 `t_C > t_F → eliminate`，不让 LLM 自己权衡（它会找理由弱化）。
- [ ] **时间证据缺失 = 降级**：onset 不可得的假设，强制贴 `hypothesis` 而非 `root cause`。
- [ ] **时钟健康监控**：监控集群时钟偏移；偏移超阈值时，扩大 Δ 并在结论里标注"时间证据可信度下降"。

## 6. 失效模式与边界

### 6.1 时钟不可靠（本根技术的天敌）

时钟漂移、NTP 跳变会让 t_C、t_F 失真。最坏情况：真因的 onset 被时钟错误地推到故障之后，导致真因被误淘汰。**对策**：用逻辑时间做主轴 + 时钟健康监控 + 容差 Δ；对时钟异常期的诊断，整体降级为 hypothesis。

### 6.2 检测延迟 ≠ 发生时刻

指标的"首次越界时刻"不是故障的"真实发生时刻"——中间有检测延迟（采样间隔、聚合窗口、告警阈值滞后）。一次瞬态故障可能在 1 分钟后才被指标捕获。如果用检测时刻当 t_F，会把因果窗口误判。**对策**：onset 检测器用变点检测（而非简单阈值越界）来逼近真实发生时刻；Δ 吸收这部分误差。

### 6.3 潜伏期故障（慢变量）

有些故障是慢变量积累到临界点才爆发的（连接池泄漏、内存碎片、磁盘满）。原因的"开始"远早于故障 onset（几小时甚至几天前的那次部署/泄漏）。简单的"t_C ≤ t_F"会漏掉这类——因为中间隔了太多事件，时间相关性看起来很弱。**对策**：对慢变量类假设，允许更大的因果窗口，并配合资源耗尽的累积曲线（而不仅是 onset 对齐）。

### 6.4 并发原因的时序纠缠

当多个原因几乎同时发生（一次部署同时改了配置和代码），时间无法区分谁才是真因。此时时间因果失效，必须依赖 [02 拓扑](02_结构因果先验_Topology-Graph.md)（谁在因果路径上）和反证检验的其它维度。**时间因果不是万能的，它是必要约束不是充分证明。**

### 6.5 "之前"被滥用成"因为"

A 早于 B 不等于 A 导致 B（post hoc ergo propter hoc 谬误）。每天日出前公鸡打鸣，不代表公鸡叫出太阳。时间因果作为**反证**（B 早于 A → 排除 A）是严格的；作为**证实**（A 早于 B → A 是因）是谬误。**严格区分**：本根技术只用于反证方向，不用于证实方向——证实留给"零反证收敛"（[01](01_反证优先_Falsification-First.md)）。

## 7. 可迁移性：网络 / 系统场景

- **网络故障**：链路 down 的物理时间 vs 业务告警时间。若 BGP 抽搐的 onset 晚于业务丢包 onset，则 BGP 抽搐是症状不是因（典型场景：底层光路先断，BGP hold-time 到期后才"抽搐"，但业务早已丢包）。
- **存储 IO**：一次大规模 IO 抖动，要区分"是底层磁盘先慢"还是"上层重试风暴先打满"。onset 对齐能直接定位。
- **数据库**：慢查询 onset vs 锁等待 onset。锁等待先于慢查询，则锁是因；反之则慢查询触发了锁升级。
- **任何带时间戳的系统**：只要事件可标记 onset，本根技术原样适用——这是它迁移成本极低的原因。

迁移时换的是**onset 的物理含义**和**容差 Δ 的标定**；"时间反向即淘汰、时间线作全局时钟、时间证据缺失则降级"的逻辑原样搬。

## 9. 一句话回到本质

> **时间戳是分布式系统里唯一全局一致、且 LLM 无法伪造的证据。用"原因必先于结果"做反证——一票否决，逻辑闭合，机器生成。这是把因果方向从相关对称性里解出来的最便宜一把刀。**
