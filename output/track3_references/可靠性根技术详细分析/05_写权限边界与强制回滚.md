# 根技术 5：写权限边界 + 强制回滚（Write Permission Boundary + Mandatory Rollback）

> **一句话本质**：把"主动恢复"从一桩风险，变成一场**有界、可逆、需人审**的受控实验。Agent 可以建议怎么修，但执行权和不可逆性必须被关进笼子。

前 4 项根技术都在讲"怎么诊断得对"。本根技术转向**"诊断之后，怎么动手才不出事"**——这是 Agent 进入生产可靠性领域的**伦理底线**，也是 AWS 选择"轻量安全"而非"重型数字孪生"的关键所在。

---

## 1. 理论谱系：Fail-Safe 与纵深防御

### 1.1 Fail-Safe Defaults（故障安全默认值）

Saltzer & Schroeder（1975）的计算机安全八原则之一：**默认访问权限应是最低的**，出错时系统应进入**安全状态**而非危险状态。映射到 Agent：

- 默认 Agent **没有写权限**——出错（诊断错）时，最坏情况是"啥也没改"，而不是"改错了一堆"。
- 写权限是**显式授予、最小化、可撤销**的例外。

### 1.2 Defense in Depth（纵深防御）

不依赖单一防线。本根技术把"安全恢复"拆成多层独立防线：

1. **权限层**：Agent 默认只能读 + 创 ticket，不能写生产。
2. **评估层**：任何变更建议前，先用 [02 拓扑](02_结构因果先验_Topology-Graph.md) 评估 blast radius。
3. **可逆层**：任何 Mitigation 计划必须含 rollback 步骤。
4. **人审层**：不可逆操作必须人确认。

任一层失效，其它层仍兜底。这比"信任单一诊断正确性"鲁棒得多。

### 1.3 可逆计算（Reversibility）与 Undo 工程

软件工程里的 undo/transaction/compensating-action 传统：**任何操作尽量设计成可逆**。数据库事务的 ACID、git 的可回滚 commit、IaC 的声明式（状态可重算）。本根技术把这条原则推到 Agent 的恢复动作上——**强制每个动作都有对应的逆动作**。

### 1.4 为什么 LLM Agent 特别需要这条

LLM 是概率系统，**必然有时诊断错**。如果诊断错 + 有写权限 + 不可逆，就是"AI 自爆生产环境"。这不是理论风险，是已经被多起真实事故（自动化脚本误删数据库、配置工具批量改错）反复验证的风险模式。把 Agent 的可靠性建立在"诊断永远正确"上是工程上的不可能命题；**建立在"诊断可能错，但错的后果有界且可逆"上才是可行的**。

## 2. 它要解决的根本问题：自动化恢复的"以错治错"

### 2.1 自动化恢复的经典两难

| 极端 | 做法 | 风险 |
|---|---|---|
| 太保守 | Agent 只报告，不动作 | 人审瓶颈，恢复慢（MTTR 高） |
| 太激进 | Agent 全自动执行修复 | 诊断错时自动放大故障（"以错治错"） |

两难的本质：**诊断的不确定性** vs **执行的可逆性**。如果执行不可逆，诊断就必须 100% 对（不可能）；如果执行可逆，诊断允许有不确定（错了就回滚）。

AWS 的解法不是在两难里二选一，而是**改变执行的性质**——把执行改造成"有界 + 可逆 + 需人审"，从而允许 Agent 大胆建议而不会酿祸。

### 2.2 反模式：全自动 self-healing

一个危险的设想："让 Agent 自动诊断 + 自动执行修复，全程无人。" 这在诊断正确时很爽，但：

- 诊断错时，Agent 自动执行了错误的修复，可能**制造第二个故障**——比原故障更难排查（因为人不知道 Agent 动了什么）。
- 多个 Agent 并发自愈时，可能互相冲突（A 在扩容，B 在缩容）。
- 没有 audit trail（除非配 [04 Journal](04_不可篡改证据链_Investigation-Journal.md)），事后无法复盘。

AWS 明确拒绝这个方向——Agent 的写权限被限制在**创建 ticket / support case** 这种低风险、可追踪的操作。

### 2.3 反模式：重型数字孪生沙盒（AWS 的轻量替代）

学术界的另一个解法：建一个高保真数字孪生，所有修复动作先在孪生里试，验证安全再上生产。问题：

- **成本高**：维护一个与生产同构的孪生环境极其昂贵（计算、数据同步、保真度）。
- **保真度难保证**：孪生永远落后于生产，"孪生里安全"不代表"生产安全"。
- **不适用网络/物理系统**：很多场景（真实流量、真实硬件故障）无法在孪生里复现。

AWS 的洞察：**不需要孪生也能达到等效安全**——用"写权限边界 + 拓扑评估 blast radius + 强制回滚"三件套，把"安全验证"从"事前模拟"变成"事后可逆"。母文档第七节的修订第 3 条明确指出：这对网络/系统场景更可落地。

## 3. 机制内核：建议权 vs 执行权的分离

### 3.1 权限矩阵（AWS 的实际边界）

| 操作类型 | Agent 权限 | 谁执行 |
|---|---|---|
| 读（指标、日志、trace、配置） | ✅ 全权 | Agent |
| 创建 ticket / support case | ✅ 允许 | Agent（写权限的边界） |
| 创建议（修复命令、配置变更、代码修改） | ✅ 可建议 | Agent 生成，**文本**形式 |
| 执行变更（部署、改配置、改代码） | ❌ 禁止 | **人**（操作员） |

关键：**Agent 能"说"怎么修，但不能"做"**。建议是文本（可读、可审、可拒），执行是动作（不可读、不可审、不可逆）。

### 3.2 强制结构化 Mitigation 计划

母文档第 5 步：输出结构化修复计划，**必须**包含五个部分：

```
MitigationPlan {
  remediation_strategy:   总策略（一句话）
  steps:                  有序步骤（每步可独立验证）
  verification_checks:    每步的验证检查（怎么知道这步成了）
  success_criteria:       整体成功标准（怎么知道修好了）
  rollback_steps:         回滚步骤（强制！没有则计划不完整）
}
```

**`rollback_steps` 是硬约束**：一个没有回滚步骤的计划，体系拒绝输出（或强制降级为"仅供参考"）。这是把"可逆性"从口号变成 schema 校验。

### 3.3 blast radius 评估先于建议

任何 Mitigation 建议，生成前先过 [02 拓扑](02_结构因果先验_Topology-Graph.md) 评估：

```
for proposed_change in plan:
    affected = topology.blast_radius(proposed_change.target)
    if affected ∩ critical_services ≠ ∅:
        flag "high_blast_radius"      # 高影响，强制人审
        require_human_approval = True
```

诊断和恢复**共用同一张拓扑图**（根技术 2 的精妙处）：blast radius 评估不需要额外的模型，直接复用诊断阶段已经构建好的图。

### 3.4 三类动作的风险分级

| 级别 | 例子 | 控制措施 |
|---|---|---|
| **低风险可逆** | 调大连接池上限、加 retry | 自动执行 + 监控 + 自动回滚（指标恶化即回滚） |
| **中风险** | 重启服务、扩容 | 人审 + 执行 + 监控 + 回滚预案 |
| **高风险不可逆** | 删数据、改 schema、删资源 | 强制人审 + 变更窗口 + 不可逆确认 |

分级让 Agent 在低风险场景能"快"（自动），在高风险场景能"稳"（人审）。这不是一刀切禁止，而是**按可逆性动态分配信任**。

## 4. 在 AWS DevOps Agent 中的具体落地

| 环节 | 写边界 + 回滚的体现 |
|---|---|
| **Mitigation** | 结构化计划（五要素，含 rollback）；写权限只到 ticket 级别；建议是文本不是动作。 |
| **Mitigation** | blast radius 评估先于建议（复用 Topology Graph）。 |
| **Mitigation** | 任何变更前评估"影响哪些 critical 服务"，高影响强制人审。 |
| **Prevention** | 推荐项（observability 增强、retry/circuit breaker、pipeline bake time 等）同样是建议，操作员接受/拒绝 + 反馈，写入 [04 Journal](04_不可篡改证据链_Investigation-Journal.md)。 |

母文档根技术 5 的工程实现三条："Agent 写权限严格限制（只能创 ticket）""任何 Mitigation 计划必须包含 rollback 步骤""Blast radius 评估先于执行建议"——三件套缺一不可。

## 5. 工程实现清单

- [ ] **权限最小化**：Agent 的 IAM/角色只授读 + 创 ticket；写生产权限一律不给。
- [ ] **建议与执行分离**：Agent 输出结构化建议（文本/schema），执行走独立的、需人触发的工作流。
- [ ] **强制 rollback schema**：Mitigation 计划 schema 校验 `rollback_steps` 非空；缺失则拒绝输出。
- [ ] **blast radius API**：复用 [02](02_结构因果先验_Topology-Graph.md) 拓扑，提供"变更→受影响服务"查询；高影响自动 flag。
- [ ] **风险分级策略**：按可逆性分低/中/高三级，各级定不同的控制措施（自动/人审/变更窗口）。
- [ ] **自动回滚触发器**：低风险自动执行的动作，配监控触发器（指标恶化超阈值 → 自动回滚）。
- [ ] **不可逆操作的人审 + 二次确认**：删数据/改 schema 类，强制人审 + 显式"我确认不可逆"。
- [ ] **变更审计**：所有执行的动作（含谁批的、何时、回滚没回滚）写 [04 Journal](04_不可篡改证据链_Investigation-Journal.md)。

## 6. 失效模式与边界

### 6.1 回滚本身不完整（compensating action 缺失）

"回滚"听起来简单，但很多操作没有干净的逆操作：删掉的邮件找不回、发出的通知撤不回、已发生的计费不能取消。如果 `rollback_steps` 只是"理论上可回滚"而实际有副作用残留，回滚就是假的。**对策**：对每类操作明确"可干净回滚 / 只能补偿 / 不可逆"三档；不可逆的强制人审 + 变更窗口。

### 6.2 自动回滚的"回滚风暴"

低风险自动执行 + 监控触发回滚，若监控本身抖动，会触发**反复执行→回滚→执行→回滚**的振荡（类似 early-cancelable 重试风暴）。**对策**：回滚触发加冷却期 + 次数上限；超过上限停止自动、升级人审。

### 6.3 blast radius 评估依赖拓扑准确性

blast radius 评估直接依赖 [02 拓扑](02_结构因果先验_Topology-Graph.md) 的准确性。拓扑过时（漏了隐式依赖）→ blast radius 低估 → 高风险操作被当成低风险自动执行。**对策**：拓扑过时风险（根技术 2 的失效模式）必须传导到这里——拓扑置信度低时，所有 blast radius 评估降级、自动执行关闭。

### 6.4 人审的"橡皮图章"风险

人审若流于形式（操作员无脑点同意），等于没有防线。**对策**：人审界面必须呈现**关键风险信息**（blast radius、可逆性、上一次类似变更的后果），而非只问"同意吗"；高风险操作要求**延迟确认**（提交后冷却 N 分钟才能批准）。

### 6.5 Agent "建议"里的隐性执行

如果建议文本里嵌了"运行这条命令"，而执行通道（如 CI/CD、运维平台）会自动跑建议里的命令，那"建议 vs 执行"的边界就形同虚设。**对策**：执行通道必须**白名单**可执行的动作，不接受 Agent 自由文本里的任意命令；Agent 建议映射到预定义的、受控的 action。

## 7. 可迁移性：网络 / 系统场景

- **网络恢复**：Agent 建议"将流量从链路 A 切到链路 B"，但执行（改路由策略/改 IGP metric）需人审 + 回滚预案（切回去）。自动场景限于低风险（如临时调低 BGP local-pref），高风险（改物理拓扑）强制人审。
- **数据库恢复**：Agent 建议"kill 会话 X / 重启连接池 / 加索引"，执行分级——kill 非关键会话可自动，改 schema 强制变更窗口。
- **K8s**：Agent 建议"重启 pod / 扩容 / 回滚到上一 revision"，K8s 原生支持 rollback（deployment rollout undo），是天然的"可逆执行"场景。
- **物理/工业系统**：回滚概念部分失效（物理动作不可逆，如已切断的电源）。此时本根技术退化为"强制人审 + 变更窗口 + 不可逆确认"，可逆层消失。

迁移要点：**先评估目标系统每类操作的可逆性**，再定风险分级；网络/云/虚拟化场景天然可逆性强，物理场景弱。

## 9. 一句话回到本质

> **不要把可靠性建立在"Agent 永远诊断正确"这个不可能的前提上。把它建立在"Agent 可能错，但错的后果有界、可逆、可审计"上——用权限边界、强制回滚、blast radius 评估把执行关进笼子，Agent 才敢大胆建议，生产才敢让 Agent 动手。**
